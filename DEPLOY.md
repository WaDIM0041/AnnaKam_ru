# Инструкция по обновлению annakam.ru

## Состав обновления (2 этапа: прошлый + текущий)

**SEO:** robots.txt, sitemap.xml, H1 на главной, JSON-LD WebSite, og:image на всех страницах, русский title 404
**Скорость:** изображения сжаты суммарно на ~5.3 МБ
**Безопасность API:** см. ниже

## Что изменено в API (безопасность)

| Уязвимость | Исправление |
|---|---|
| `GET /api/settings` отдавал пароль админа всем | Публичный доступ теперь только к белому списку флагов (`show_pricing` и др.); полный список — только по токену, пароль не отдаётся никогда |
| Пароль хранился открытым текстом | Хеш bcrypt; старый пароль автоматически конвертируется при первом входе |
| Токен = пароль, передавался в URL | Случайные токены сессий (7 дней), только заголовок Authorization |
| Брутфорс без ограничений | Максимум 5 попыток входа за 10 минут с одного IP |
| SSRF через импорт картинок по URL | Функция удалена полностью |
| CORS `*` | Только https://annakam.ru |
| Fallback-пароль `admin123` в коде | Удалён |
| Выполнение PHP в /uploads/ | Новый uploads/.htaccess запрещает |

## Порядок действий на хостинге

### Шаг 1. УДАЛИТЬ со старого сайта (замена файлов их не удаляет):
```
/api/install.php
/api/db-probe.php
/api/_diag.php
/_local_old_backup/
/INSTALL/
```

### Шаг 2. Загрузить с заменой:
```
.htaccess                  (корень)
robots.txt
sitemap.xml
index.html
404.html
privacy/index.html
terms-of-use/index.html
api/.htaccess
api/common.php
api/auth.php
api/settings.php
api/upload.php
api/migrate-password.php   ← временный, удалить после шага 3!
uploads/.htaccess          ← НОВЫЙ файл
portfolio/*.webp           (все 6)
uploads/*.jpg, *.webp      (изменённые картинки)
```

### Шаг 3. Сменить пароль админки (обязательно!):
1. Открыть `https://annakam.ru/api/migrate-password.php`
2. Задать новый пароль (мин. 10 символов)
3. **Сразу удалить** `api/migrate-password.php` с сервера
4. В админке перелогиниться с новым паролем

Примечание: если пароль пока не сменён, старый продолжает работать (автоматически переводится в хеш при первом входе).

### Шаг 4. MySQL-пароль (желательно):
Пароль из `api/config.php` засвечен локально. Код его НЕ использует (API работает на SQLite), поэтому можно просто **удалить `api/config.php` с сервера**. Либо сменить пароль БД в cPanel.

## Проверка после загрузки
- `https://annakam.ru/api/settings` → только флаги вида show_pricing, БЕЗ admin_password ✅
- `https://annakam.ru/api/settings` с Bearer-токеном из админки → полные настройки без пароля ✅
- 6 неверных паролей подряд на `/admin/` → блокировка «Повторите через 10 минут» ✅
- `https://annakam.ru/uploads/test.php` → 403 ✅
- `https://annakam.ru/` → 301 на https://annakam.ru (без www) ✅
- Яндекс.Вебмастер + Google Search Console: переобход главной

## Известное поведение после обновления
- После смены пароля через админку все сессии сбрасываются — нужно перелогиниться.
- Публичный сайт использует дефолтные значения флагов, если они не заданы в настройках — это норма.

## Замечено, но требует решения вне кода
1. `yandex-verification` в index.html — заглушка `yandex_verification_code_here`. Нужно вставить реальный код из Яндекс.Вебмастер или удалить мета-тег.
2. В корне лежит папка `_new_backup_2208/` (~12 МБ снимок сайта от 22.08) — не загружать на сервер; содержит старую копию api/config.php с паролем.
3. Видимый H1/h2 на главной возможны только после пересборки Next.js из исходников.
